Всё страница: гибрид Notion и Obsidian на памяти Кизуны

Запись, заметка, человек, проект, решение и встреча это одна сущность с видом kind. У страницы есть типизированные свойства с provenance, тело в markdown и связи двух сортов: [[ссылка]] из текста и свойство-ссылка из схемы. Списки, доска и календарь это не экраны, а сохранённые запросы.

Все данные ниже примерные и кликабельные: ссылки ведут на страницы, свойства показывают источник при наведении, виды переключаются.

1. Страница проекта, скомпилированная из записей

Слева виды страниц вместо папок. В центре страница: свойства сверху, как в Notion, тело в markdown, как в Obsidian, а внутри тела встроенный вид с открытыми делами проекта. Справа то, чего нет ни у Notion, ни у Obsidian: из каких записей страница собрана и кто на неё ссылается.

    2. Один запрос, четыре раскладки

    «Сегодня», «Журнал TODO», «Доска» и «Заметки» становятся предустановленными видами: фильтр по kind и свойствам плюс раскладка. Колонки доски живут в настройках вида, а не в отдельной таблице. Тот же вид можно вставить в тело любой страницы кодовым блоком.

    3. Ввод: markdown в хранении, блоки в поведении

    Хранится обычный markdown, поэтому переносимость и неизменяемый raw не страдают. Поверх него два меню из Notion: @ вставляет ссылку на страницу и заполняет свойство, / вставляет конструкцию разметки. Блоки нужны только как поведение редактора.

    @ упоминание
    Завтра в 11 созвон с @Са по секретам сессий в Hub, подготовь контекст
    Страницы · «Са»
    В тексте останется [[Саша]], а в свойство «Участники» встанет ссылка с provenance «указано человеком».
    / команда
    Решили хранить секреты сессий в Vault
    /
    Вставить
    Каждый пункт превращается в обычную разметку: callout, чекбокс, кодовый блок вида, ссылка на блок. Без собственного формата.

    4. Шесть примитивов

    Что взято у кого и где твоя добавка. Ничего лишнего: формул, произвольных схем и блочного хранения на старте нет.

    Page kind

    Одна сущность для всего. Тело в markdown, версии append-only. У страницы-записи первая версия это raw, и она заблокирована.

    Obsidian: всё заметкаNotion: база это страницаraw неизменяем

    Property schema per kind

    Дата, ссылка, список ссылок, перечисление, флаг. Схема задаётся на kind. У каждого значения есть тип знания и уверенность.

    Notion: типизацияObsidian: frontmatterfact / inference · confidence

    Link typed edge

    Одно ребро графа для [[ссылки]] из текста, свойства-ссылки и встраивания. Один индекс даёт backlinks и relations.

    Obsidian: backlinksNotion: relationrollup считает агент

    View query + layout

    Сохранённый фильтр и раскладка: список, доска, календарь, таблица. Встраивается в тело страницы кодовым блоком.

    Notion: database viewsObsidian: Basesэкраны = виды

    Block ref ^id

    Якорь блока уже понимает рендерер Кизуны. Цитата решения на странице проекта живёт в исходной записи и не расходится с ней.

    Obsidian: ^block-idNotion: synced blockцитата с provenance

    Template per kind

    Шаблон тела и свойств на kind. Агент заполняет его при компиляции записей, человек при ручном создании.

    Notion: templatesObsidian: Templaterзаполняет ingest

    5. Экспорт: папка, которую открывает Obsidian

    Свойства уходят в frontmatter, вложенность в папки, виды в файлы Bases, ссылки остаются ссылками. Это и есть переносимость: из Notion такой экспорт теряет relations, здесь терять нечего.

    kizuna-export/ ├─ projects/ │ ├─ Hub.md │ └─ Hub/ │ └─ Секреты сессий.md ├─ people/ │ ├─ Саша.md │ └─ BE-команда.md ├─ decisions/ │ └─ Секреты сессий в Vault.md ├─ captures/ │ └─ 2026/09/02/ │ ├─ 13-57 созвон с BE.md │ └─ 14-20 решили про Vault.md ├─ views/ │ ├─ Сегодня.base │ ├─ Журнал TODO.base │ └─ Доска.base ├─ attachments/ ├─ index.md └─ log.md
