# Поиск задач в Telegram

Поиск — плагин общего Telegram-меню. Он добавляет «Найти» в строку рядом с «Сегодня» и «Другой день» и команду `/find`. После «Что найти?» следующий собственный текст становится запросом. После результата или «Отмена» обычный текст снова сохраняется. Пересылка и файл отменяют ожидание запроса и проходят прежний capture flow.

Примеры: «Какие просьбы Саши я ещё не сделал?», «Какие у меня вообще дела были связаны с Петей?», «За прошлую неделю», «Что я ему обещал?». Последние два запроса могут уточнять предыдущий поиск, если человек снова нажал «Найти» в течение десяти минут. Без установленного человека местоимение вызывает уточнение. Отмена, другие команды, календарные действия, пересылка, новая привязка и сброс журнала очищают контекст.

## Зависимость от PR общего меню

Этот PR поставлен поверх общего меню и сводок с ограничением доступа через `PAGENT_TELEGRAM_DAY_SUMMARY_USER_IDS`. Поиск наследует тот же список конкретных аккаунтов; роль администратора доступа не даёт. В этой базе `createTelegramService().menuRouter` доступен; `server/index.js` устанавливает поиск в существующий роутер. Diff поиска не копирует реализацию меню/сводок и не создаёт второй dispatcher. Минимальное расширение общего роутера предоставляет проверку доступа для плагина и видимость добавленной кнопки по текущему пользователю. Если поисковый модуль подключить к старой базе без общего роутера или API проверки доступа, установка вернёт `shared_menu_router_required` и кнопка не будет опубликована.

`server/index.js` вызывает `installTelegramTaskSearch` сразу после создания Telegram service. Общий роутер предоставляет:

- `registerPreflight(handler)` до изменения режимов и fallback capture: `{update,link,message,callback,interactions,send}`; `true` прекращает обработку.
- `registerMessageRoute(handler)` до shortcut «покажи пятницу» и потребления pending text.
- `registerPendingMode(name,{accept,consume(link,text,data,message)})` с исходным текущим сообщением.
- `registerCallbackRoute(handler)` после обязательного ACK и проверки private/from/current binding.
- `registerReplyKeyboardButton(text,{row,visible})`, `replyKeyboard(link)` и `interactions.begin/get/clear`. `visible(link)` фильтрует добавленную кнопку в обеих ветвях клавиатуры; обычные расширения без предиката сохраняют прежнее поведение.
- `canAccessMenu(link)` проверяет действующую привязку и существующий общий предикат доступа. Поиск использует его перед новым запросом/callback и после ожидания; отдельного списка разрешений у поиска нет.
- `send(link,text,replyMarkup)` с повторной проверкой действующей привязки.
- `beforeLinkCommand(message,{update})` вызывает preflight привязанного пользователя и очищает его режим до обработки `/start CODE`.

`/start CODE` проходит preflight и очистку старого режима: базовый `take()` вызывает `menuRouter.beforeLinkCommand(message,{update})` до `linkWithCode()`. Это сохраняет начальное подключение непривязанного пользователя, а для привязанного обеспечивает очистку и защиту от повторного `/start CODE`. Совместные тесты проверяют неверный код, последующий capture и повтор старого кода при новом поиске. Поисковый diff сохраняет этот порядок.

`additionalCommands()` публикует `TASK_SEARCH_COMMANDS` только после успешной установки плагина. Глобальный slash-menu содержит только `help`; в разрешённых действующих личных чатах отдельно регистрируются `DAY_SUMMARY_COMMANDS`, `help` и команды поиска. Для остальных привязок старый chat scope удаляется. После новой привязки используется тот же общий предикат. Hook `onCaptureSaved({captureId,userId,messages,link})` записывает источники после успешной постановки capture в очередь; index повторно проверяет владельца и текущую привязку. Для split child источник родителя автоматически не приписывается.

## Что подтверждает поиск

Поиск охватывает только собственные текущие и завершённые задачи. Удалённые записи, произвольные заметки, контейнеры разделённых действий и обычные подзадачи не входят в выдачу. Закрытие задачи определяется последними событиями ledger, отмена закрытия учитывается. Завершённый экземпляр повтора обозначается отдельно; серия остаётся открытой.

Используются слова, формы русских имён и слов, а также небольшие группы близких понятий: документы/бумаги, отчёт/сводка, оплата/платёж, проверка/проверить, отправить/прислать/выслать, звонок/позвонить/созвон. Это ограниченный структурированный поиск, без LLM/embedding retrieval; произвольные смысловые перефразировки могут не найтись.

Автор пересылки, явный проситель, упоминание и участник обсуждения — разные основания. Просьба автора пересылки требует самостоятельного обращения в исходном тексте. Собственное сообщение «Саша попросил…» требует сохранённого, самостоятельного и нецитируемого высказывания. Обещание владельца требует собственного явного высказывания; чужая речь и Telegram blockquote не становятся обещанием владельца. Смешанные пачки не получают общего автора просьбы. Старые записи не обогащаются вымышленными ID и ролями; роли без достаточного источника могут не найтись.

Одинаковые известные имена требуют уточнения полным именем, @username или почтой участника. Упоминание имени без ID не подтверждает личность. Саша не объединяется автоматически с Александром.

«За прошлую неделю» означает прошлые понедельник–воскресенье в часовом поясе пользователя. По умолчанию период проверяет добавление **или** фактическое выполнение; в ответе это подписано. Явные «созданные», «выполненные», «запланированные» и «срок» выбирают соответствующее основание. Неявная дата `defaulted` не считается сроком. Неверная дата вызывает уточнение, а не поиск за всё время.

Ответ содержит до шести задач, статус, доступные даты, основание связи с человеком и кнопки открытия. Источник Telegram показывается только при сохранённой проверенной публичной ссылке на пост канала. Ссылка на личное сообщение не конструируется. Вся история читается порциями; превышение бюджета явно показывает неполное покрытие.

## Состояние и проверки

Ожидание текста, последние критерии и страницы ограничены десятью минутами и действующей привязкой; карты ограничены 256 элементами. Минимальное намерение поиска сохраняется до ожидания: одна строка на Telegram-подключение с владельцем, привязкой/поколением и временем истечения, без запроса и результатов. После перезапуска следующий новый текст при таком намерении получает явное сообщение о сбросе поиска и **не сохраняется**. Затем можно снова нажать «Найти» или писать обычную задачу. Истёкшее намерение и сброс/смена привязки также защищают первый текст от неожиданного capture; отмена, команда, callback или пересылка очищают намерение. Уже потреблённые обновления отдельно защищены durable receipts.

Отзыв общего разрешения блокирует новый поиск и поздний результат, очищает критерии и страницы. Остальные пользователи сохраняют обычные тексты, пересылки и файлы; уже потреблённый запрос при повторе остаётся заблокированным даже после отзыва доступа.

Каждое новое действие меняет ревизию взаимодействия. Поздний результат старого запроса или страницы не отправляется и не заменяет критерии/страницы нового поиска. Ошибка уведомления об отмене поиска не препятствует сохранению пересылки или файла.

Receipts резервируются перед ожиданием и поиском по стабильному chat/message или callback ID. Они не содержат запросов, переживают перезапуск, смену привязки и reset. Reset очищает только собственные origin metadata, увеличивает поколение контекста и помечает собственное незавершённое намерение истёкшим: первый текст получит сообщение о сбросе вместо неожиданного сохранения. Экспорт источников ограничен владельцем; operational receipts/intent не являются выгрузкой содержимого журнала. Callback содержит непрозрачный серверный токен, без user ID или критериев; чужая или истёкшая страница не раскрывает результат.

Проверки без внешних отправок: `node --test tests/task-search.test.js tests/telegram-search.test.js`. Тесты используют SQLite, fake общего роутера и fake Telegram fetch; проверяют запросы, цитаты, режимы, отмену, пересылки/файлы, повторные обновления и restart/reset, собственность, смену привязки, страницы, лимиты и более 500 записей истории.

`tests/telegram-search-integration.test.js` загружает реальные router/service из общей реализации, без копирования её кода. Если модули ещё не сведены в эту ветку, можно указать `PAGENT_SUMMARY_WORKTREE=/path/to/summary/worktree node --test tests/telegram-search-integration.test.js`. При отсутствии зависимости интеграционные тесты явно skipped; это не подтверждение интеграции. Они автоматически используют модули текущей ветки. Совместные тесты используют реальный общий allowlist: проверяют отказ другому активному администратору, доступную владельцу кнопку, личный scope команд, ACK без утечки и отзыв доступа во время запроса/страницы. HTTP и production bot smoke поиска в текущем окружении не выполнялись: локальный TCP listen запрещён. Частный preview выполняет только владелец PR сводок по отдельному разрешению пользователя; реализация поиска реальных сообщений не отправляет. Merge и deploy ожидают решения пользователя после preview. Перед merge требуется smoke совместного меню, особенно `/start CODE`, общего slash-menu и callback ACK.
