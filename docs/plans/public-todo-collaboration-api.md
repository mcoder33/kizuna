# Public todo collaboration API (backend contract)

All routes use the existing cookie session and Origin policy. Errors are `{error:{code,message}}`; unauthorized 401, forbidden/revoked 403, unavailable 404, stale revision/idempotency conflict 409. Do not join on view/login; consent is explicit.

## Publication and guests
- `POST /api/captures/:id/public-shares` `{circleId}` → 201 `{id,token,circleId,createdAt,url}`. `url` is `/s/:token`. The token is shown once; only its SHA256 is stored. Every created link is stable until revoked.
- `GET /api/captures/:id/public-shares` → `{shares:[{id,circleId,createdAt,revokedAt}]}` for capture author. Cannot recover plaintext token; cache a copied link per user/capture/share on client, or create another.
- `DELETE /api/captures/:id/public-shares/:shareId` → `{revoked:true}`. Does not remove existing circle members/association.
- `/s/:token` serves `public/public-todo.html` (frontend-owned). No-store/noindex/no-referrer. Well-shaped unavailable/revoked tokens serve the same HTML shell with HTTP404 so registration return can explain that the account is usable and offer app entry. Shell never embeds token/capture/user/private data. Malformed token404 may be JSON; projection/join APIs remain JSON404 and never grant membership.
- `GET /api/public/todos/:token` → exactly `{title,body,state,circleName}`; state is `active` or `completed`. No captureId/circleId/people/children/history/attachments/Yjs.
- Guest `EventSource('/api/public/todos/:token/events')`: event `todo` carries the same current allowlist; event `revoked` carries `{}` then stream closes. Guest has no mutation or awareness transport.
- `POST /api/public/todos/:token/join` authenticated `{consent:true}` → `{captureId,circle,returnTo}` where returnTo is `/#today?open=<captureId>`. Rechecks token inside transaction; owner preserved, member upgraded to editor; no duplicates. Missing consent → `consent_required`. Removed/left users → `membership_removed`. Revoked/deleted link → `share_unavailable`.
- `DELETE /api/circles/:id/members/:userId` owner only → `{removed:true}`.
- `POST /api/circles/:id/members/:userId/restore` owner only → `{restored:true}`. Explicit restoration clears rejoin denial and reinstates previous role. Owner cannot remove an owner. `GET /api/circles/:id` circle detail adds owner-only `removedMembers:[{id,name,email,initial,avatar,role,leftAt}]` bounded500 for restore discovery; other members receive no removedMembers field.

## Card capabilities
`GET /api/captures/:id` entry includes `mine`, `canEdit`, `canComplete`, `canPublish`, `myCircles`, `circles`, `collaboration`.
`canEdit` is author OR active editor of a shared circle OR an active circle owner who explicitly consented via public join. Migration29 stores the separate can_edit grant (default0); join sets it while preserving owner role and management. Existing owners/members gain no edit rights without consent; remove/leave disables the active membership, explicit restore preserves its previously consented grant. Existing owner/member role does not grant editing another person's record. `canPublish` is capture author with an active circle membership (the existing invite permission).
`collaboration` is null for captures that have never been shared; once initialized its lifetime remains canonical even after the final circle association is removed, and the author retains editor access; otherwise `{enabled:true,generation,revision,structureRevision}`. All shared circle todos initialize their own canonical document on access, including ones without a public link.
`GET /api/captures/:id/collaboration` → `{enabled,canEdit,generation?,revision?,structureRevision}`. Use for list-created cards missing full metadata. Readable legacy members stay readonly. `canComplete` separately preserves accepted assignment completion permission; editors/authors can complete. Every canonical update triggers existing authenticated journal SSE, so readonly circle viewers refetch the sanitized authenticated card and see current title/body without editor WS.
Notes-tree overview, child lists and full page/detail serializers all preserve `documentRevision` (null if personal never-canonical) and `collaboration:{enabled:true,generation,revision}|null`, read with the same canonical body/title SQL projection; legacy notes actions use that captured revision for the first save, then the returned entry.note.revision for successive saves; stale baselines receive409.
`entry.note.body` and `entry.interpretation.classification.summary` are the CURRENT canonical values; raw/author/history remain original.

## WebSocket
Attach to the same app.listen server: `/api/collaboration/:captureId` using same-host ws/wss and session cookies. Origin is required. Upgrade requires editor rights and existing circle share. No unauthenticated y-websocket endpoint.
Frames are JSON, Yjs bytes are standard base64. Yjs13 `Y.Doc` has exactly roots `doc.getText('body')`, `doc.getText('title')`. Empty title is allowed during typing, UI fallback `Без названия`. Body <=20000 chars, title <=500; frame <=1MiB, awareness frame <=4KiB.

Server immediately sends:
`{type:'hello',generation,revision,update,actor:{id,name},structureRevision}`
Apply update with a remote origin excluded from local UndoManager. BEFORE replay merge, check fresh authorization/hello; scope IndexedDB by user+capture+generation. Generation mismatch must not replay previous document.
Client sends `{type:'sync',stateVector:<base64>,clientId:<doc.clientID>}`.
Server responds `{type:'sync',update:<base64 diff>,revision}`. Initial hello snapshot is authoritative durable state. Offline local changes can then be sent as a diff against hello stateVector, never full text replacement.
Client update `{type:'update',operationId:<UUID>,baseRevision:<integer>,update:<base64 Yjs update>}`. A concurrent baseRevision is valid because CRDT merges. Keep operationId stable for retry.
Server broadcasts `{type:'update',update:<base64 state>,revision,structureRevision}` only after SQL commit, then acknowledges sender `{type:'ack',operationId,revision,replayed}`. Only ack means saved; full snapshot updates deduplicate naturally in Yjs. All mutation, sync and broadcast operations recheck the actual current cookie session and ACL.
Server error `{type:'error',code,operationId}`. Common codes `invalid_envelope`, `invalid_update`, `invalid_document`, `missing_dependencies`, `update_too_large`, `document_too_large`, `idempotency_conflict`, `rate_limited`, `invalid_awareness`. Invalid updates do not poison server canonical state. On rejected update retain copyable local draft; recreate/sync a clean document rather than reuse poisoned local operations indefinitely.
Server terminal `{type:'revoked',code:'access_revoked'}` then close1008. Do not replay/reconnect automatically on1008 without a new authorized page/session. Logout/block/reset/membership loss rechecks active channels immediately at HTTP finish and every heartbeat.

## Awareness
Client sends `{type:'awareness',clientId:<same as sync>,clock:<awareness.meta local clock>,state:null|{cursor?,selection?,user?}}`. Cursor/selection are standard relative-position JSON supplied by the Yjs CodeMirror binding, not text offsets. Client user field is ignored; server overrides name/color/actorId.
Server broadcasts `{type:'awareness',states:[{clientId,clock,state}]}`. State includes server-owned `{user:{name,color},actorId}` plus cursor/selection. Convert these JSON states into standard y-protocols awareness bytes (lib0 encoder: varUint count, then for each varUint clientId, varUint clock, varString JSON.stringify(state)), then `applyAwarenessUpdate(awareness,bytes,remoteOrigin)`. Null state removes disconnected cursor. No awareness is sent to guests. Avoid rebroadcasting remote-origin awareness changes.

## Structure and legacy saves
`POST /api/captures/:id/commands` `{operationId,expectedRevision:<structureRevision>,command}`.
Commands: `{type:'completion',completed:<boolean>,occurrence?:'YYYY-MM-DD'}` or `{type:'subtask.create',title}`.
Result includes `structureRevision`; create additionally `{captureId,entry}`, completion `{completed,occurrence?}`. Stable operationId deduplicates; mismatched expectedRevision →409 and reload tree/current revision. Completion applies all current actionable projections, preserves repeat-instance semantics. Children inherit only explicit currently authorized shared circles; old private children remain private.
Journal SSE `journal` invalidates structure/state/cards. Keep active collaborative editor document/bindings mounted across refresh; refresh surrounding projections/props only.
Legacy `POST /api/captures/:id/notes` requires `{body,expectedRevision:<document revision>}` once canonical document exists; stale/missing revision409. Title corrections use `{patch:{summary,...},expectedRevision}`; unrelated corrections preserve CURRENT canonical title. Existing internal synchronous writers apply Y.Text splice operations; async AI reclassification cannot overwrite live human title/body. Offline replay uses Yjs updates, not these legacy replacement routes.

## Persistence and deploy
Yjs state, audit update/actor/revision, current body/title and projection titles commit atomically. Old note versions retained; materialized note versions checkpoint at <=2Hz while activeNote reads durable current body immediately. New runtime dependencies pinned Yjs13/y-protocols/ws. Browser bundle owned by frontend must be reproducible. Caddy existing reverse_proxy supports WS and SSE; no proxy edits required. Tests/custom createServer app users can call `app.collaboration.attach(server)`; app.listen automatically attaches. `app.closeEventStreams()` closes collaboration/guest sockets/timers too.
