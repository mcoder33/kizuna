# Контракт памяти Pagent

## Назначение

Пользователь фиксирует мысль текстом или голосом и не выбирает папку. Каждая запись создаёт неизменяемый `Capture.raw`. Агент строит версии интерпретаций и обратимые представления, но не меняет источник истины.

## Сущности и связи

- `Capture` — исходный текст или расшифровка голоса, время, канал, язык и согласие на хранение. `raw` неизменяем.
- `Interpretation` — версионированное прочтение Capture: типы `meeting/event`, `task`, `note`, `outcome/decision`, `idea/question`.
- `Claim` — поле с `value`, `kind: fact|inference|assumption`, `confidence` и `provenance` (фрагмент Capture, правило или пользовательское подтверждение).
- `Correction` — отдельное событие исправления с причиной; `supersedes` ссылается на прежнюю интерпретацию, а не переписывает её.
- `PersonalRule` — видимое, отключаемое правило, появляющееся после трёх одинаковых подтверждённых corrections.
- `Projection` — обратимая проекция в день, календарь, задачу, проект или бриф. Это не источник истины.
- `ActionProposal` — предложение внешнего действия; его нельзя выполнить без отдельного подтверждения.

Один Capture может породить несколько сущностей и проекций. Связи между похожими записями — только предложение, не дедупликация с удалением.

## Инварианты

1. Raw никогда не переписывается и не удаляется Undo.
2. Любое поле имеет provenance, тип знания и confidence.
3. История append-only: correction создаёт новую версию и связь `supersedes`.
4. Projection можно отменить и детерминированно собрать заново из Capture и принятых интерпретаций.
5. Неизвестное не превращается в выдуманный факт.
6. Закрытый проект не реактивируется молча; forgotten commitment показывается только с явным источником.
7. Бриф read-only и показывает provenance каждой важной детали.

## Машина состояний

`CAPTURED → TRANSCRIBED → INTERPRETED → CONFIDENCE_GATE → SILENT_APPLIED | AWAITING_CONFIRMATION | AWAITING_CLARIFICATION → PROJECTED → ACTION_PROPOSED → CONFIRMED | REJECTED → CORRECTED/SUPERSEDED`.

`TRANSCRIBED` нужен только голосу. `SILENT_APPLIED` создаёт внутренние Projection и предлагает Undo. `ACTION_PROPOSED` обязателен для `calendar.create/update`, сообщений, изменения сроков и закрытия задач; эти операции всегда ожидают отдельного `CONFIRMED`.

## Confidence policy

| Условие | Поведение |
|---|---|
| Существенные поля ≥ .90 и нет конфликта | Тихо создать внутренние проекции, показать Undo |
| Тип ≥ .75, одно важное поле .55–.89 | Компактное подтверждение этого поля |
| Тип < .75 или конфликт даты/проекта | Один конкретный вопрос |
| Нет факта | Сохранить как note/idea без догадки |

Низкая уверенность сама по себе не требует вопроса: если запись не содержит действия, даты, внешнего запроса или конфликта, её безопасно сохранить как `note_unclassified` с raw, внутренней Projection и Undo. Вопрос нужен только когда классификация необходима для запрошенного действия, времени или внешнего поведения.

```js
// input
{ raw: 'Завтра в 11 созвон с BE по секретам сессий в Hub, подготовь контекст' }
// output (сокращённо)
{ type: {value:'meeting', confidence:.96}, claims:[
  {field:'time', value:'завтра 11:00', kind:'fact', confidence:.94, provenance:'Завтра в 11'},
  {field:'project', value:'Hub', kind:'fact', confidence:.98, provenance:'в Hub'},
  {field:'followUp', value:'prepare brief', kind:'inference', confidence:.91, provenance:'подготовь контекст'}
], decision:'SILENT_APPLIED', projections:['day','upcoming','brief'], undo:true }
```

```js
{ raw: 'В среду после обеда созвон с Сашей' }
{ type:{value:'meeting', confidence:.88}, claims:[
  {field:'time', value:'среда после обеда', kind:'fact', confidence:.72, provenance:'после обеда'}
], decision:'AWAITING_CONFIRMATION', question:'Во сколько поставить встречу?' }
```

## Безопасная автоматизация

Агент может предложить связь, дедупликацию, следующее действие или бриф. Он не создаёт/не меняет календарь, не шлёт сообщения, не двигает дедлайны и не закрывает задачи без отдельного подтверждения. Undo отменяет только созданные Projection и ActionProposal, сохраняя Capture и историю.

## Граничные случаи

- Две даты или проекты: один конкретный вопрос, без проекции во внешний календарь.
- Отмена: отменяет проекцию; исходная запись остаётся доступна.
- Повтор: предложить связь с существующей записью, не сливать автоматически.
- Перенос: новая Correction supersedes прежнюю интерпретацию.
- «Мы решили»: decision/outcome с provenance, не задача по умолчанию.
- Закрытый проект: показать статус и спросить о реактивации.
- Ошибка голоса: хранить transcript как непроверенный, предложить исправить.
- Отрицание («не отправлять»): не предлагать действие без подтверждения.
- «Когда-нибудь»: idea/note без срока и календарной проекции.

## Privacy и retention

Минимизировать доступ, шифровать хранимые Capture, позволять экспорт и удаление по политике пользователя. Голосовая расшифровка и LLM — явные режимы с обозначенным провайдером и сроком хранения. В этой модели они mock и ничего не отправляют по сети.
